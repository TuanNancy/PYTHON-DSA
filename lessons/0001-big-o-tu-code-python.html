Đọc Big O
từ code Python

Trong phỏng vấn, một lời giải chạy đúng chưa đủ. Bạn cần nói được hiệu năng thay đổi thế nào khi đầu vào lớn lên.

Chiến thắng của bài này: nhìn một đoạn code có vòng lặp và xác định được time complexity của nó.

1. Big O trả lời câu hỏi nào?

Gọi n là kích thước đầu vào. Big O mô tả tốc độ tăng của lượng công việc khi n tăng. Ta quan tâm xu hướng tăng, nên bỏ hằng số và các hạng nhỏ hơn.

3n + 10 thao tác được rút gọn thành O(n). Khi n đủ lớn, phần tăng tuyến tính quan trọng hơn số 3 và 10.

2. Một vòng lặp

def contains_zero(numbers):
    for number in numbers:
        if number == 0:
            return True
    return False

Trong worst case, số 0 nằm cuối hoặc không tồn tại. Vòng lặp kiểm tra cả n phần tử, nên time complexity là O(n).

Phỏng vấn: hãy nói rõ trường hợp đang xét. Hàm trên có best case O(1), nhưng worst case O(n).

Kiểm tra nhanh 1

Nếu list có 1.000 phần tử và không chứa số 0, thân vòng lặp chạy bao nhiêu lần?

3. Hai vòng lặp lồng nhau

def all_pairs(numbers):
    for left in numbers:
        for right in numbers:
            print(left, right)

Vòng ngoài chạy n lần. Với mỗi lần đó, vòng trong lại chạy n lần. Tổng cộng là n × n, hay O(n²).

Kiểm tra nhanh 2

Hai vòng lặp, mỗi vòng duyệt toàn bộ list nhưng chạy nối tiếp nhau, có Big O nào?

4. Bài tập phỏng vấn mini

Không chạy code. Hãy trả lời ba câu sau:

def has_duplicate(numbers):
    for i in range(len(numbers)):
        for j in range(i + 1, len(numbers)):
            if numbers[i] == numbers[j]:
                return True
    return False
  1. n đại diện cho gì?
  2. Worst-case time complexity là gì?
  3. Best-case time complexity có thể là gì?

Gửi ba câu trả lời cho tôi. Tôi sẽ chấm và chỉ mở bài tiếp theo khi phần nền này đã chắc.

Ghi nhớ

Một vòng duyệt toàn bộ dữ liệu thường gợi ý O(n). Hai vòng lồng nhau cùng phụ thuộc vào n thường gợi ý O(n²). Đây là cách đọc ban đầu, không phải quy tắc thay thế việc đếm cẩn thận.
