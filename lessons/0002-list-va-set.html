12 phút · Cấu trúc dữ liệu

Chọn List
hay Set?

Một cấu trúc dữ liệu phù hợp có thể biến lời giải kiểm tra mọi cặp thành lời giải chỉ duyệt đầu vào một lần.

Chiến thắng của bài này: dùng set để kiểm tra phần tử đã xuất hiện và giải bài phát hiện trùng lặp trong O(n).

1. Hai cấu trúc, hai thế mạnh

list giữ thứ tự và cho phép phần tử trùng nhau. Nó phù hợp khi cần truy cập bằng vị trí như numbers[2].

numbers = [4, 7, 4]
print(numbers[1])  # 7

set chỉ giữ các giá trị duy nhất. Nó phù hợp khi câu hỏi là: “Giá trị này đã xuất hiện chưa?”

seen = {4, 7}
print(4 in seen)  # True
print(9 in seen)  # False
Điểm đánh đổi: kiểm tra membership trong set có average case O(1), nhưng set không dùng để truy cập phần tử theo index.

Kiểm tra nhanh 1

Bạn cần lưu các mã đã gặp để kiểm tra mã mới có bị trùng không. Cấu trúc nào phù hợp hơn?

2. Từ mọi cặp đến một lượt duyệt

Thay vì so sánh mỗi phần tử với mọi phần tử phía sau, ta tạo một set tên là seen để lưu những giá trị đã gặp.

def has_duplicate(numbers):
    seen = set()

    for number in numbers:
        if number in seen:
            return True
        seen.add(number)

    return False

Với [4, 7, 4], chương trình hoạt động như sau:

  1. Gặp 4: chưa có trong seen, thêm 4.
  2. Gặp 7: chưa có trong seen, thêm 7.
  3. Gặp 4: đã có trong seen, trả về True.

Mỗi phần tử được duyệt nhiều nhất một lần. Kiểm tra và thêm vào set có average case O(1), nên tổng thời gian là O(n).

Đổi lại, seen có thể lưu tối đa n phần tử, nên space complexity là O(n).

Ghi nhớ

Nếu bài toán thường xuyên hỏi “đã thấy giá trị này chưa?”, hãy nghĩ đến set. Tốc độ tốt hơn không miễn phí: ta dùng thêm bộ nhớ để tránh lặp lại phép so sánh.
